# Nexus 0.2.4: dump files, workspaces in one step and more

## 🗄 Import a dump file

Load a `.sql` or `.sql.gz` file into a database, also from a `.zip`, `.tar` or `.tar.gz` file. In the app, "Import a database" has the new source "A dump file…", and each database on the Site screen has "Import dump…". In the terminal, use `nexus db import ~/Downloads/shop.sql.gz`. PostgreSQL also reads a file of `pg_dump -Fc`.

A database that exists changes only after your choice: replace only the tables in the dump, or replace the whole database. Nexus puts a copy of the old database in the trash first.

## 🌳 A dump file for each new workspace

A site can give each new workspace a dump file, for example a scrubbed copy of production. Choose "Dump file…" under Workspaces on the Site screen. A Laravel or Node.js workspace gets the dump in its main database, and then its migrations run.

For WordPress, Nexus changes the links of the live site while the dump loads. So the workspace opens with its own URL at once. Nexus changes serialized data, JSON and URL-encoded links correctly, and email addresses and other sites stay as they are. You can add more live URLs, for example a staging site.

## ⚡ Workspaces in one step

- `nexus workspace create <branch>` and the "New workspace…" button make the git worktree and the workspace. Settings > Workspaces chooses the place of new worktrees.
- Extra files for each workspace: a site can name files that git ignores, for example `.env.testing` or `auth.json`. Each workspace gets a clone, with the database and the URL of the workspace.
- Commands before the removal of a workspace, for example `php artisan queue:clear`.
- A WordPress workspace with a copy of the database changes its links faster: WP-CLI now reads only the tables with a link.

## 🛠 And more

- `nexus open` and `nexus edit` open the site of the current folder in the browser or in your editor.
- `nexus db connection`, `nexus db databases` and `nexus db create` show the database connection of a site, list the databases on its server and make an empty database. No command drops a database.
- A document root setting for a project that does not use `public/`.
- Each PHP version loads PCOV for code coverage. Nexus turns it on only for a command with `--coverage`, for example `pest --coverage`. So pages, queue workers and Composer stay fast.
- PHP 8.2 to 8.5 have `mailparse`. A new install of PHP turns it on.
- A name that Nexus does not know gets a page with a list of your sites. A PHP site shows a wait page while PHP starts.
- Errors show as plain sentences, not as raw texts of macOS.

# Nexus 0.6.5: a clear log of each stop, and coding agents that keep working after an update

## 📋 The activity log tells what happened

The activity log of Nexus now has a line for each start and stop of a service. Each stop names its cause, for example an update or a click in the app.

- **A stop from outside Nexus.** When a service ends without a request from Nexus, the log says so. It also says how the service ended, for example with a crash or a stop signal of another program.
- **Workspaces.** The log shows when Nexus adds a workspace, sets it up, starts or stops its database server and removes it.
- **Plain words.** A service that stops too often now tells you in plain words how it ended the last time, for example "The last time it crashed (signal 11)."

## 🤖 Coding agents keep working after an update

An MCP server of Nexus that ran before an update said "Nexus does not run now" after the update. Nexus ran, but the old MCP server could not reach it.

- **The MCP server starts the new version itself.** Your coding agent sees no break and needs no restart.
- **The `nexus` command tells you.** A command that ran during an update now says that Nexus was updated, and asks you to run it again.
- This works from the update after 0.6.5, because the running version decides.

## 🛠 Fixes

- The "Port in use" window could stop the wrong program when you clicked Stop much later. Now Nexus checks the program again just before the stop.
- After a crash of the background service, Nexus also checks each old program again just before it stops it.

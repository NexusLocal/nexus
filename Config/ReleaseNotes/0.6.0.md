# Nexus 0.6.0: idle workspaces stop, dev servers start on demand and old workspaces go

## 💤 Workspaces stop when nobody uses them

A workspace without activity now stops after 1 hour. Its database servers, its background processes and its Node.js app stop. So a project with many worktrees no longer fills the memory of your Mac.

- **It starts again by itself.** The next page, command or database connection starts the workspace again. The first page waits about half a second.
- **Database apps keep working.** TablePlus, `mysql` and PhpStorm connect to a stopped workspace as usual. Nexus holds the port and starts the server at the first connection.
- **Activity** is a page, a command through Nexus (`php`, `composer`, `wp`, `node` or `npm`), a request of `nexus` or of an agent, and a git change.
- **Your choice.** Settings > Workspaces > "Stop after" goes from 15 minutes to 1 day, or Never. The new "..." menu of a workspace row has "Stop when idle", "Stop Now" and "Start".
- `nexus workspace stop` and `nexus workspace start` do the same. `--keep` turns "Stop when idle" off. The MCP server has the new tools `stop_workspace` and `start_workspace`.
- A stopped workspace stays stopped after a restart of Nexus or of your Mac.

## ⚡ Dev servers start with the first page

Vite (`npm run dev`) of a Laravel site and the app of a Node.js site now start when you open a page. They stop when no page loads and no tab is open for 5 minutes. The first page shows "The dev server starts" for a few seconds.

- Settings > Sites > "Stop a dev server after" has 1, 5, 15 and 30 minutes, and Never.
- Nexus starts no second Vite next to a Vite that you run yourself. It removes a `public/hot` that a crash of Vite left.
- When a dev server does not start, the page shows why and names its log.

## 🧹 Old workspaces

The Site screen now shows a line such as "5 workspaces have no activity for 5 days" with "Review…". The sheet lists each old workspace with its last activity and what git knows about it: merged, branch gone on the remote, commits not pushed, changes not committed or locked.

- Choose the workspaces that can go and remove them in one step. Nexus never removes a workspace by itself.
- A notification names the old workspaces of a site, each day by default. Settings > Workspaces has "Old after" and "Notify again". Settings > General turns the notification off.
- `nexus workspace list --old` shows them in the terminal. `--days 3` uses another number of days.

## 🗑 Remove one workspace

The "..." menu of a workspace row and a right click on the row have "Remove Workspace…". The alert names the folder that git removes, the branch that stays and the dump of its databases in the trash.

- Nexus first checks that git can remove the worktree. A worktree with changes that are not committed stays, and the alert has "Show in Finder".
- A worktree that git locked stays too. Claude Code locks its worktree while its session runs. So the menu item is off while that session runs.

## 🛠 And more

- The commands before removal of a site no longer run in a workspace that git then keeps.
- A stop of Nexus now takes at most about 40 seconds, also with many database servers.
- The MCP tool `remove_workspace` now names the time of the trash in Settings > Workspaces.
- Swift Crypto 5.1.1 and SwiftASN1 1.7.4.

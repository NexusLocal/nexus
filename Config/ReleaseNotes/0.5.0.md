# Nexus 0.5.0: queries, Xdebug on demand and help for your projects

## 🔎 Queries, log lines and jobs in the dump viewer

Each request on the Dumps screen now also shows its database queries, its log lines and its queue jobs. This works for Laravel and WordPress sites, without a change in your code.

- **Queries** show the SQL with its values, the time and the line in your code that ran it. Nexus marks a slow query, a duplicate query and an N+1 query.
- **Log lines** show the level, the message and the context as a tree. Other PHP sites show their PHP errors and warnings here.
- **Jobs** show the jobs that a request put on a queue. In a queue worker each job is its own entry with its status, its time and its own dumps, queries and log lines. WP-Cron events and Action Scheduler actions show as jobs too.
- **Your choice.** The Dumps screen has a switch for each kind: "Catch queries", "Catch log lines" and "Catch queue jobs".
- The web page of the dumps, `nexus dumps` and the new MCP tool `read_dumps` show them too.

## 🔔 Notifications open the right place

A click on a notification of Nexus now opens the screen that it is about. A new mail opens the Mail screen with the site of the mail and the mail itself. A ready workspace opens its site and marks its row. A service that stopped or failed opens that service. An import opens its database. This also works while Nexus runs only in the menu bar.

## 🐛 Xdebug only when you debug

Xdebug no longer makes your normal pages slower. With the Xdebug switch on, only a request that starts a debug session uses Xdebug. An example is a request from the browser extension Xdebug helper. All other requests stay fast.

- **One command with Xdebug.** `nexus debug artisan my:command` runs one command with Xdebug, also while the switch is off. It also works with `php`, `composer`, `wp` and a PHP file such as `vendor/bin/pest`.
- **Other commands never load Xdebug.** `php`, `composer` and `wp` in your terminal stay fast. Your code editor can still load Xdebug for a test run with its own setting for the Xdebug extension.

## 🧭 Help for a project that you add

When the `.env` of an added Laravel site points to another place on your Mac, the Site screen says so. Examples are an `APP_URL` of MAMP PRO, its database or its Redis. "Use Nexus…" shows each key with its old and its new value. When the old database server still runs, Nexus can copy your data first. Nexus changes the `.env` only after the copy. The old values stay as comment lines.

## ⚙️ Your own nginx and Apache lines

Each PHP site can have its own nginx or Apache lines, for example `client_max_body_size 100m;`. Write them on the Site screen or with `nexus site lines shop.test "<lines>"`. Nexus checks them with `nginx -t` or `httpd -t` first. When a line has an error, the editor marks it and the site keeps its old lines. Each workspace gets the same lines as its site.

## 📦 More .wpress backups

The import of a WordPress site now reads a backup of All-in-One WP Migration with a password. Nexus checks the password while you type. `nexus import` asks for it, or reads it with `--password-stdin`. A backup that an extension compressed with gzip or bzip2 needs no question.

## 🛠 And more

- A command of a site that starts from another folder now shows with its site on the Dumps screen. An example is `php ~/Sites/shop/artisan schedule:run` in a crontab.
- A workspace now clones a database only when the main site really uses that database of Nexus. A `.env` with `DB_HOST=localhost` gets a clear message, because PHP then uses another server.
- Each tab of Settings is as tall as its content. A long tab such as Network scrolls inside the window.
- "Find agents" and "Restart" show their result in a banner, as "Check for updates" does.

# Nexus 0.6.4: a faster switch to each new version, and safer removals

## 🔄 A new version starts sooner

After an update the background service of Nexus first ends its current work. Then it starts the new version. From now on it does not wait for the setup of a workspace. The setup goes on after the switch.

- **Only the commands wait.** The switch waits while a setup runs the commands of your site, for example `php artisan migrate`. A migration that stops halfway can break the database of the workspace.
- **From the next update on.** The running version decides when it switches. So you see the change at the update after 0.6.4.

## 💬 A clear message after an update

A newer `nexus` command or a coding agent can send an option that the older background service does not know. Before 0.6.4 the older service ignored that option without a message.

- **The request stops.** The background service now refuses a request with an option that it does not know.
- **You know what to do.** The `nexus` command and the MCP server tell you to run the command again in a minute.
- This also works from the update after 0.6.4.

## 🛠 Fixes

- A workspace removal that stopped halfway wrote the dumps of its databases a second time. An example is a removal during a logout. Now each database gets one dump.
- A stop during the delete of the database files of a workspace could leave a part of them. The removal then failed each hour. Now the next start deletes the rest.

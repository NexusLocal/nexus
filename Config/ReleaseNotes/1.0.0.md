# Nexus 1.0: move from Herd or Valet, and signed packages

## 🚚 Move from Herd or Valet

Nexus finds Laravel Herd or Laravel Valet on your Mac. Click "Move from Herd…" or "Move from Valet…" on the Overview. The sheet shows each item first, and you choose what moves.

- **Sites.** Parked folders, linked sites with their aliases, proxies and the PHP version of each site. An old PHP gets PHP 8.2. Your own nginx lines move too.
- **Databases and Redis.** Nexus copies each database from the server in the `.env` or `wp-config.php` of the site, for example DBngin, Homebrew or Herd Pro. The copy runs while Herd or Valet still runs. The Redis keys move too.
- **Settings.** Your `php.ini` lines, the `.env` of each Laravel site, the lines of Herd in `~/.zshrc` and project files with the PHP of Herd, such as `.mcp.json`. Nexus keeps a copy of each file that it changes.
- **One step for you.** Quit Herd with one click, or run `valet stop`. Then Nexus takes over ports 80 and 443 and the domain `.test`, and it opens each site once.
- **Nothing in Herd or Valet changes.** The report tells you what moved and how to go back.
- **The command line.** `nexus import herd` and `nexus import valet` do the same.

## 🔏 Signed packages

- **Only packages that the maintainer signed.** Each list of packages on GitHub now has a signature that the maintainer makes outside GitHub. Nexus installs and updates nothing from a list without a valid signature, and it refuses a list that is older than the last one it read. Your installed packages keep working.
- **Checked sources.** The build of each package checks its sources against the checksum or the PGP signature of the publisher.

## 🛠 Fixes

- **A second try.** A download of a package tries once more after a connection that stopped.

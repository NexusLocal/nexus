# Nexus 0.2.2: fixes for tools, workspaces and downloads

A small update with fixes that came from daily use.

## 🧭 php and composer follow the project in the arguments

An MCP server of an editor often starts `php /path/to/project/artisan` from another folder. Nexus then used the PHP version for new sites. Now the folder in the arguments decides when it is a site of Nexus: the script of `php` and `node`, `composer --working-dir`, `npm --prefix` and `wp --path`. A script outside a site, for example a phar in `~/bin`, keeps the PHP version of the current folder.

## 🌳 Workspaces wait for your own worktree scripts

Some projects prepare each new worktree with a script that copies `vendor` or runs `composer install`. Such a script ran at the same moment as the setup of Nexus. The workspace then got a warning about `vendor`, or it became Not isolated. Now Nexus keeps a folder that another program makes. It waits until `vendor` and `node_modules` stop changing before it checks the application.

## 🛠 And more

- `nexus wp` now works on a site whose `wp-config.php` stops each request without HTTPS. Before, WP-CLI ended without output.
- "Send mail to Nexus" now also turns off `MAIL_ENCRYPTION=tls` for Laravel 8 and older. Their mailer asks for STARTTLS, which the mail service of Nexus does not have.
- When GitHub gives an error for the list of packages or for a package, Nexus tries the GitHub API once. On the first start this showed as "HTTP status 504".
